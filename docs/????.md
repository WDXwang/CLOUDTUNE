# CloudTune 技术方案

> 本文档说明 CloudTune（云盘音乐）的整体架构、分层设计、关键数据流与天翼云盘直连接入实现。接口可行性与端点细节见同目录下两份调研报告。

---

## 1. 总体架构

应用采用 **MVVM + 分层 + 手动依赖注入**，整体分为四层：

```
┌──────────────────────────────────────────────────────────┐
│  UI 层（Jetpack Compose）                                 │
│  Screens / ViewModels / Navigation / Theme / Components   │
└───────────────▲──────────────────────────┬───────────────┘
                │ 观察 StateFlow / 调用      │ 调用
┌───────────────┴──────────────────────────▼───────────────┐
│  播放层（Media3）                                         │
│  PlaybackService(MediaSessionService)                    │
│  PlayerControllerManager(MediaController)                │
│  CloudMedia / CloudStreamResolverFactory / 缓存          │
└───────────────────────────────┬──────────────────────────┘
                                 │ resolveStream / 播放
┌───────────────────────────────▼──────────────────────────┐
│  领域 / 仓库层（Repository）                              │
│  MusicRepository：屏蔽后端差异、收藏、配置                │
└───────────────────────────────┬──────────────────────────┘
                                 │
┌───────────────────────────────▼──────────────────────────┐
│  数据层（Data Source）                                   │
│  CloudDataSource 接口                                     │
│   ├─ WebDavCloudDataSource（PROPFIND / GET，连 AList）    │
│   └─ TianyiCloudDataSource（非官方 Web API，Cookie）      │
│  DataStore（配置） / Room（收藏）                         │
└──────────────────────────────────────────────────────────┘
```

**组合根**：`CloudTuneApp`（Application）在 `AppContainer` 中创建并持有所有单例（SettingsStore、AppDatabase、MusicRepository、PlayerControllerManager），不引入 Hilt，降低多模块协作与构建复杂度。

## 3. 核心数据模型

- `ServerConfig`：后端类型（`WEBDAV` / `TIANYI_DIRECT`）及各后端的连接参数。
- `CloudFile`：云端文件 / 文件夹统一抽象。`id` 在 WebDAV 下为相对路径，在天翼直连下为文件数字 ID。
- `MusicTrack`：可播放音轨（标题、艺术家、专辑、时长 + 所属 CloudFile）。
- `StreamSource`：解析后的真实播放 URL + 所需请求头（直链有效期短，现取现用）。

---

## 4. 关键数据流

### 4.1 浏览目录

```
BrowserScreen → BrowserViewModel
   → repository.list(dir)
   → 当前 CloudDataSource.list(dir)
       WebDAV  : PROPFIND(Depth:1) → 解析 multistatus XML
       天翼    : listFiles.action 分页 → 解析 JSON
   → 文件夹在前、音乐在后排序 → Compose 列表渲染
```

### 4.2 播放（在线流式）

为避免把“短期有效的直链”固化进播放列表，播放器使用 **占位 URI + 播放前解析**：

1. `CloudMedia.mediaItem(file)` 把 `CloudFile` 序列化后编码进自定义 URI：
   `cloudtune://track?data=<Base64(JSON(CloudFile))>`。
2. ExoPlayer 加载该 URI 时，`ResolvingDataSource` 拦截，解码出 `CloudFile`，
   同步调用 `repository.resolveStream(file)` 得到真实 `StreamSource`，
   替换 URI 与请求头。
3. 外层 `CacheDataSource` 用 `SimpleCache` 对已读音频块做边播边缓存。

```
MediaItem(cloudtune://...)
   → CacheDataSource（命中则直接读缓存）
   → ResolvingDataSource（现取直链 + 鉴权头）
   → OkHttpDataSource（HTTP GET，支持 Range/206）
   → 天翼 CDN / AList
```

### 4.3 后台播放 / 通知栏

`PlaybackService` 继承 `MediaSessionService`，持有 ExoPlayer 与 `MediaSession`。系统通知栏、锁屏控制、蓝牙 / 耳机媒体按键由 Media3 自动处理；前台服务类型为 `mediaPlayback`。

### 4.4 收藏

`toggleFavorite` 将 `MusicTrack`（含序列化的 `CloudFile`）写入 Room `favorites` 表；`observeFavorites` 以 Flow 方式驱动收藏界面，收藏列表可直接回放。

## 5. 天翼云盘直连实现要点（路线 A）

> 非官方接口，来源为天翼云盘 Web / H5 站点，社区在 AList、cloudpan189-api 中使用。

- **登录态**：用户粘贴浏览器 Cookie，所有请求带 `Cookie` 与浏览器 User-Agent（不收集明文密码）。
- **获取 accessToken**：`GET api.cloud.189.cn/open/oauth2/ssoH5.action`，跟随重定向，从最终 URL 的 `accessToken` 查询参数取值并进程内缓存。
- **列目录**：`GET api.cloud.189.cn/listFiles.action?folderId=&pageNum=&pageSize=100&iconOption=5&mediaAttr=0&orderBy=lastOpTime&descending=true`，根目录 ID 为 `-11`，循环分页；解析 `fileListAO.fileList`。
- **取直链**：`GET api.cloud.189.cn/open/file/getFileDownloadUrl.action?fileId=`，请求头
  `accesstoken`、`timestamp`、`signature = md5("AccessToken="+token+"&Timestamp="+ts+"&fileId="+id)`；
  解析 `fileDownloadUrl`（`res_code=0`）。
- **流式播放**：直链为 CDN 地址，支持 HTTP Range（206）、通常 302 跳转、小时级有效期，过期用同 fileId 重取。

### 已知局限

- 登录已上滑块验证码，故采用 Cookie 方式；Cookie 过期需重新获取。
- 接口参数 / 签名 / 端点可能随官方调整失效，需对照 `docs/` 报告与最新抓包维护。
- 自签名 HTTPS 的 AList 暂未内置信任选项。

## 6. 扩展方向

- 内置 WebView 授权页（可在官方页面扫码登录），免手动复制 Cookie。
- 播放时解析内嵌 / 在线封面与歌词。
- 家庭云（familySessionKey / familyId）浏览。
- 均衡器、播放统计、多主题。

---

## 7. 风险与合规

- 直连路线使用非官方接口，可能违反天翼云盘服务协议，存在风控 / 封号风险。
- 推荐 WebDAV + AList 路线，将登录与风控隔离在用户自控的服务端；优先使用 Cookie / 扫码，避免留存明文密码。
- 本项目仅用于个人学习与技术研究。
